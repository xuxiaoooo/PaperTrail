# 开发与构建

Electron 管理窗口、菜单栏快览和开机启动。界面通过应用内部 `papertrail://app` 地址访问本地 Python 后台，稿件保存在 SQLite 中。

Mac 和 Windows 安装包使用系统已安装的 Google Chrome，不打包或下载浏览器。Electron 内置的 Node 用于运行读取脚本，无需另带一份 Node。运行前需安装 Chrome。

## 构建

需要 Node.js 24 和 Python 3.13。

```sh
npm ci
python3 scripts/prepare_runtime.py macos-arm64
npm test
npm run package:mac
npm run verify:package
npm run smoke:package
npm run release:collect
```

Windows 在 Windows 电脑上执行 `python scripts/prepare_runtime.py windows-x64`，再执行 `npm run package:win`。Mac 使用对应的 `package:mac` 命令。所有投稿入口使用系统 Google Chrome；ScholarOne 读取使用有界面模式。

`npm run release:collect` 汇总 Mac 和 Windows 安装包到 `release/`。

`build/runtime/`、`build/work/`、`build/test-results/` 和 `release/` 为本地生成目录，不提交到仓库。图标源文件位于 `assets/`，修改后运行 `node scripts/make-icons.cjs`。

## 开发检查

- `npm test`：后台、桌面逻辑和读取器测试。
- `node scripts/smoke-desktop.cjs`：在独立空白数据目录运行桌面流程。
- `node scripts/smoke-browsers.cjs`：启动系统 Google Chrome。
- `npm run smoke:package`：检查本机已打包应用。
- `npm run verify:package`：检查包内运行组件、架构和数据隔离。
- `node scripts/audit-package.cjs windows-x64`：检查 Windows 安装包的组件完整性与浏览器排除。
- `node scripts/smoke-first-launch.cjs`：以空白数据目录和不可用的下载代理检查首次启动、Chrome 与再次启动。
- `node scripts/smoke-windows-installer.cjs`：在独立 Windows 测试环境实际安装，检查 Chrome、首次启动与再次启动。

`PAPERTRAIL_TEST_EXECUTABLE` 指定待测应用，`PAPERTRAIL_TEST_RUNTIME` 指定其 runtime。正常使用时无需设置这些变量。

GitHub Actions 在 Pull Request 或手动触发时构建并检查 Mac 与 Windows 安装包。

## 版本与发布

公开版本在补丁为零时显示 `1.0`、`1.2` 等两段格式，补丁版本显示 `1.2.1` 等三段格式；`package.json` 始终使用三段格式。

更新版本时同步 `package.json`、锁文件和发布说明。完成构建后，在 GitHub Releases 创建 `v1.2.1` 形式的标签并上传 Mac 和 Windows 安装包。新版“检查更新”从 GitHub 最新正式 Release 选择适用安装包，要求 GitHub 提供 SHA-256 digest，并在安装前验证；`updates.json` 继续供旧版客户端使用。

Chrome 通道参考 [Playwright 浏览器管理](https://playwright.dev/docs/browsers#google-chrome--microsoft-edge)，Windows 安装流程使用 [electron-builder NSIS 扩展](https://www.electron.build/nsis/)。
